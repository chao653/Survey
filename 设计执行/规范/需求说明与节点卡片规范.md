# 需求说明与节点卡片规范

> 文档状态：现行规范（通用，跨项目复用，内容不绑定具体项目）
> 本文规定 Figma 设计稿画布上两类标注卡片的使用方式：
>
> 1. **需求说明卡片**（组件 `Utility / Feature Card`）：向读稿人交代设计背景、负责人和项目入口的说明卡。
> 2. **节点卡片**（Title 标题卡，组件 `Utility / File Section Headers`）：标记 Section 内功能列、流程列或状态列，QA 与前端按节点卡对稿。
>
> 两类卡片是同一套交付标注体系，总是配套出现，故合并成一份规范维护。

## 1. 名词与范围

### 1.1 Page 全局说明卡

每个 Figma Page 一张，放在该 Page 的全局说明区域，说明该 Page 下各 Section 和 UI 稿共用的上下文：

- Page 主题和设计背景。
- Designer 与 Product Manager。
- PRD 和 Linear 入口。
- 适用范围。
- 后续 UI 稿的使用规则。

Page 全局说明卡只对当前 Page 生效，不得复制其他 Page 的说明卡直接代替。

### 1.2 Section 项目卡

放在具体 Section 内，说明该 Section 承载的功能 / 题型 / 模块的适配或设计工作。与 Page 全局说明卡共用 `Utility / Feature Card` 组件，但用途不同，不能互相替代。

### 1.3 节点卡片（Title 标题卡）

放在 Section 内每列顶部，标记该列的功能、流程或状态，使用 `Utility / File Section Headers` 组件，颜色通过 Variant 切换（如 `Property 1=Yellow` / `White`）。

## 2. 共用铁律

以下规则对两类卡片一律生效：

### 2.1 组件使用

- 必须复用现有组件实例，必须保留组件连接，不 detach instance。
- 不得用普通 Frame、Rectangle 或手画卡片替代组件。
- 当前 Page / Section 已有同用途卡片时，更新或续用现有实例，不重复创建；已存在的卡片优先调整周围内容，不删卡重建。

### 2.2 信息来源

内容按以下顺序确认：

1. 用户当前明确提供的信息。
2. 用户指定的 PRD、Linear issue 或 Figma 节点。
3. 当前 Page 已确认的说明卡。
4. 本项目现有执行记录。

Designer、Product Manager、日期、PRD 链接、Linear issue、功能范围和交付状态一律不得自行推测。

### 2.3 跨迭代规则

项目存在新旧迭代（如从旧版设计稿续作新版）时：

- 旧迭代的卡片只作为历史背景或结构参考。
- 不得直接沿用旧卡的字段内容；新建 / 更新时重新核对。
- 不得为了完成新迭代而修改旧迭代的来源卡片。

### 2.4 位置与边界

- 卡片放在各自规定区域（见 §1），互相之间及与状态画板不得重叠。
- 所有直属节点必须位于 Page 或 Section 边界内，不得裁切或溢出。

### 2.5 文案

- 使用最终功能 / 题型 / 模块名称，不拼接版本号，不使用已废弃的旧名称。
- 指代产品或功能时使用项目确认的正式全名（在项目自己的口径文档中确认）。
- 英文大小写按同目录 `写作规范.md` 执行。

## 3. 需求说明卡片专属规则

### 3.1 标准字段

| 字段 | 填写规则 |
| --- | --- |
| Title | 使用最终功能名 / 题型名 / 模块名，不拼接版本号 |
| Description | 一句话说明该 Section 的设计范围；同类 Section 用统一句式（模板在项目执行文档中确认） |
| Designer | 填写已确认的设计负责人；未确认时使用 `-` |
| Product Manager | 填写已确认的产品负责人；未确认时使用 `-` |
| Date Started | 使用当前项目确认的开始日期 |
| Date Finished | 未完成时使用 `-`，完成后填写真实日期 |
| PRD | 填写真实 PRD 链接；未确认前保留 `[PRD Link]`，不得猜填 |
| Linear | 填写对应的真实 Linear issue |

### 3.2 Description

不得自行扩写未经 PRD、Linear 或用户确认的功能范围。

## 4. 节点卡片专属规则

### 4.1 颜色规则（当前迭代 vs 来源 Section）

- **当前迭代** Section 的标题卡使用项目确认的高亮 Variant（每个项目开工时确认用哪一色，记录在该项目的执行文档中，如 Grading Studio 2.0 用 `Yellow`）。
- **来源 / 历史** Section 的标题卡保持原有 Variant（通常 `White`），不得为了新迭代顺手改色。
- 如果某个来源 Section 当前已经是高亮色，先确认它是否为已批准例外，不得仅凭版本名称直接改色。
- 高亮 Variant 与设计系统具体 token（如 `brand/yellow/*`）的映射在正式确认前不写死，视觉结果以组件 Variant 为准。

### 4.2 标题文案

- 标题文字以当前功能、PRD 或用户指定的真实功能和状态为准。
- 从来源 Section 复制续作时，默认保持原英文标题，不增删、不改写。
- 中文翻译只用于沟通和对照；除非用户明确要求，不写入 Figma 标题卡。
- 新建或修改标题时必须去掉首尾空格。

### 4.3 列结构

- 一列只放一张标题卡。
- 同一列有多个状态画板时，状态画板纵向排列在标题卡下方。
- 标题卡必须与下方状态画板一一对应，不能出现错列、跨列或重复标题卡。
- 标题卡和对应状态画板应位于同一目标 Section 的列结构中。
- 不得把新增标题卡或状态画板放回来源 Section。
- 默认不额外创建无业务意义的子 Section；当前 Page 已有确认的子 Section 结构时续作现有结构，不重复创建。

### 4.4 图层命名

标题卡实例使用英文语义名称，推荐格式 `{Title} Header`，例如 `Default Header`、`Grade with AI Header`、`Not Submitted Header`。

不得使用 `Frame 1`、`Header Copy`、`Header / 1`、`Rectangle 8` 等无语义名称；名称表达业务含义，不使用颜色或外观作为名称。

### 4.5 尺寸与间距

标题卡尺寸、列间距和坐标没有全局硬规则，历史页面的数值只是该页布局参考。执行新 Page 或调整现有 Page 时：

- 先读取当前目标 Section 和相邻列结构。
- 优先沿用当前 Page 已确认的组件尺寸和对齐方式。
- 内容或边界发生变化时重新计算布局，不盲目套用历史坐标。
- 不得因为套用其他 Page 的参考值造成重叠、裁切或超出 Section。

## 5. 标准执行顺序

### 5.1 需求说明卡片

1. 确认用户指定的 Figma Page、Section 和节点。
2. 读取当前 Page 的全局说明卡。
3. 查找目标 Section 中现有的 `Utility / Feature Card`。
4. 核对 Title、Description、负责人、日期、PRD 和 Linear。
5. 只更新已确认信息，未知字段保留 `-` 或 `[PRD Link]`。
6. 检查组件连接、位置、边界、文本溢出和图层命名。

### 5.2 节点卡片

1. 确认来源 Section 和目标 Section。
2. 核对目标列的真实功能、状态和英文标题。
3. 复用 `Utility / File Section Headers` 实例。
4. 将当前迭代实例设置为项目确认的高亮 Variant。
5. 保持来源 Section 实例不变。
6. 按列放置标题卡和状态画板。
7. 检查组件连接、Variant、标题文案、图层命名和布局边界。

## 6. 验收清单

### 6.1 需求说明卡片

- [ ] 使用现有 `Utility / Feature Card` 实例，组件连接未被 detach。
- [ ] Title 使用最终名称，未拼接版本号。
- [ ] Description 符合项目确认的统一句式。
- [ ] Designer、Product Manager、日期、PRD 和 Linear 均有可靠来源，未确认的信息没有被猜填。
- [ ] 没有沿用旧迭代的负责人、日期或范围。
- [ ] 卡片位于正确的 Page 或 Section，没有重叠、裁切或文本溢出。

### 6.2 节点卡片

- [ ] 使用 `Utility / File Section Headers` 实例，组件连接未被 detach。
- [ ] 当前迭代标题卡为项目确认的高亮 Variant。
- [ ] 来源 Section 标题卡未被误改。
- [ ] 标题文字正确，且没有首尾空格。
- [ ] 一列只有一张标题卡，与下方状态画板一一对应。
- [ ] 图层使用 `{Title} Header` 等英文语义名称。
- [ ] 没有重复卡片、错列、重叠、裁切或文本溢出。
- [ ] 已同时完成节点结构检查和截图视觉检查。

## 7. 当前待补充项

以下内容尚未形成已确认的全局标准，确认前以现有组件实例、当前 Page 已确认布局和用户指定节点为准，不自行补造：

- `Utility / Feature Card` 的统一宽高、padding、间距和长文本规则。
- 说明卡各字段的统一字体、字号和行高。
- 高亮 Variant 与设计系统色板 token 的正式映射。
- 所有 Page 共用的标题卡尺寸、列间距和坐标。
- 标题过长时的最大宽度、换行、截断或 tooltip 规则。
