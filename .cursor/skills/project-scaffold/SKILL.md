# 新项目脚手架（Asher 设计项目标准结构）

## 执行约定

- 项目名取当前工作区文件夹名。
- **不要逐项提问**：全部内容用「待填」占位一次性创建完，最后统一列出需要用户补的信息。
- **零信息先索要**：没有任何可指导创建的信息时，先向用户索要一次；用户没有或表示后续补充，则只创建空文件夹结构，模板文件留待信息到位后再生成。
- 已存在的文件跳过不覆盖，只补缺的。

## 目录结构（一次性全部创建）

```
<项目根>/
├── AGENTS.md                    # 项目入口：任务路由 + 决策顺序
├── 决策日志.md                   # 全项目拍板记录（新决策置顶）
├── .cursor/rules/
│   └── <项目名小写>.mdc          # 项目口径（alwaysApply: true）
├── 需求文档/                    # PRD 溯源 + 常设容器
│   ├── 00_PRD溯源.md
│   ├── 01_产品规则.md
│   └── 待确认问题清单.md
├── 设计执行/
│   ├── 规范/                    # 设计系统四件套 + figma 偏好 + 卡片/写作规范 + 编排检查标准
│   ├── 日志/                    # Figma 操作日志（按类型组文件，README 定格式）
│   └── 验收/
│       └── 验收报告模板.md
├── 设计方案/                    # HTML demo 探索区
│   └── README.md
├── 走查/
│   ├── 00_走查清单框架.md
│   └── 截图/
├── 需求调研/
│   ├── 登录说明.md
│   ├── 抓取结果/                 # 按抓取需求建分类子目录（原始产物）
│   └── 调研文档/                 # 基于抓取产出的调研文档
└── Linear/
    ├── AGENTS.md
    └── History.md
```

## 各文件模板要求

### 根目录

**`AGENTS.md`** — 项目入口，含五节：
1. **项目范围**：一句话产品范围 + Linear ticket 链接（待填）。
2. **任务路由表** `| 任务类型 | 必读文件 |`，至少含：设计系统/token/基础组件 → `设计执行/规范/design.md` + `components.md` + `icons.md`；Figma 读写/绘制 → `设计执行/规范/figma-preferences.md`（必读，固化 token/组件来源）+ `设计执行/规范/figma-layer-naming.md` + `需求文档/01_产品规则.md`；卡片类产出 → `设计执行/规范/需求说明与节点卡片规范.md`；英文 UI 文案撰写/大小写走查 → `设计执行/规范/写作规范.md`；Figma 操作记录落盘 → `设计执行/日志/`（格式见其 README）；历史决策与口径追溯 → `决策日志.md`（新会话先读顶部 5 条）；多方案探索 → `设计方案/README.md`；设计走查 → `走查/00_走查清单框架.md`；验收报告 → `设计执行/验收/验收报告模板.md`；产品网站取数/截图/行为验证 → `需求调研/登录说明.md`（用 Playwright MCP，原始产物按抓取需求分类存 `需求调研/抓取结果/<抓取需求>/`，一个需求一个文件夹；基于抓取产出的调研文档归 `需求调研/调研文档/`）；Linear 工单 → `Linear/AGENTS.md`。
3. **决策顺序**：用户当前指令 > 用户指定的节点/PRD 范围 > `需求文档/01_产品规则.md` 已确认规则 > 本地执行文档与走查结论 > 通用判断；冲突影响业务规则或交付结论时先请用户确认。
4. **Figma 工具铁律**：一律用 Figma MCP；不可用时说明原因、经用户确认后才可换途径；在 Figma 完成操作后把记录写入 `设计执行/日志/`，走查轮次产物仍归 `走查/`，两边不混。
5. **输出要求**：简体中文、大白话；结论区分「已确认 / 设计判断 / 需用户确认」。

**`决策日志.md`** — 全项目拍板记录，产品口径与设计执行的决策都记这里。文件头写明约定——新决策**置顶**追加；推翻旧决策不删原文，新增 `[修订]` 条目；新会话先读顶部 5 条。

个人通用习惯 memory 是**全局规则**（`~/.cursor/rules/memory.mdc`，`alwaysApply: true`），所有工作区自动加载。脚手架**不要**在项目里创建或复制 memory 文件；跨项目的新习惯直接维护进全局那份。

**`.cursor/rules/<项目名小写>.mdc`** — 项目口径，`alwaysApply: true`：术语表（英文术语+中文解释）、产品范围边界、测试站 URL 与默认视口，均待填。

### 需求文档/

- **`00_PRD溯源.md`**：PRD 来源（Notion 链接/本地文件，待填）+ 章节锚点表 `| 锚点 | PRD 章节 | 对应设计文档/节点 |`——走查按锚点逐项核对。
- **`01_产品规则.md`**：已确认规则清单 `| 规则 | 来源 | 状态 |`。
- **`待确认问题清单.md`**：`| # | 问题 | 背景 | 提给谁 | 状态 |`——PRD 说不清时不替 PM 猜，进这里回标。

### 设计执行/

- **`规范/` 八份文档一律从本技能 `references/` 整套复制**（随技能自带：`design.md`、`components.md`、`icons.md`、`figma-layer-naming.md`、`figma-preferences.md`、`写作规范.md`、`命名规范.md`、`需求说明与节点卡片规范.md`，调整要点见 `references/README.md`）。若共享 `../设计系统/` 或最近项目里存在**更新**的版本（对比文件修改时间），以更新者为准，并提醒用户刷新技能快照。
- 复制后按项目调整：**`figma-preferences.md`**（模板版，agent 每次 Figma 绘制/修改前必读）——确认三库口径是否沿用 Kira 默认（组件 `ShadCN-Default` / token `Design System 2.0 Foundations` / 图标 `Design System 2.0 Icons`），`<项目名>` `<日期>` 占位替换，业务组件白名单随设计推进逐条登记；**`写作规范.md`**——标题行与 §五「专有名词清单」换成当前项目的产品术语；**`命名规范.md`**——页面编排与交付检查标准四项待填。
- 其余五份通用直接用；若项目用的不是 Kira 设计系统，`design.md` 改用 Figma MCP（`get_variable_defs` / `search_design_system`）从对应库重新导出生成。
- **`日志/`**：Agent 在 Figma 操作后的记录区。建 `README.md` 写明：文件按**类型**组织，一个类型一个文件（如 `需求卡片和标题.md`、`节点N_<主题>.md`），新类型出现时新建对应文件；同一类型后续操作（含用户会话外的手工修改补记）在文件末尾按日期追加「`## YYYY-MM-DD · 摘要`」小节，只增不覆盖；每条记录含任务来源、涉及节点（node_id + Figma 链接）、操作摘要、结果状态；截图证据归 `日志/参考截图/`（命名 `YYYY-MM-DD-<说明>.png`）；走查轮次产物归 `走查/`，不放这里。
- **`验收/验收报告模板.md`**：交付节点清单 `| 模块 | node_id | Figma 链接 | 状态 |` + 验收结论区。QA 开 ticket 以此为输入。

### 设计方案/

- 建 `README.md` 一行说明：HTML demo 探索区，技能不限，方案选定后落回 Figma。

### 走查/

- **`00_走查清单框架.md`**：双轨 checklist——**A. PRD 对齐**（按 `00_PRD溯源.md` 锚点表逐项）；**B. 规范合规**（token 绑定、auto layout、命名、UI 文案大小写、字重与图标规则）。并写明轮次产物约定：每轮产出 `RN_报告.md` + `RN_修改清单.md`；修改清单含状态列（待改/已改/搁置），修改后在**同一份清单**复核勾销，不另开文件。
- `截图/`：走查证据，与报告成对存放。

### 需求调研/

- **`登录说明.md`**：写成 agent 可直接执行的格式——测试站 URL（待填）、默认视口 1440x900、角色账号表 `| 角色 | 账号 | 密码 | 登录后落点 |`（待填）、逐步登录路径。文件头加提醒：密码不写进 `.cursor/rules/`、不外贴 Notion/Linear；项目若进 git，此文件加入 `.gitignore`。
- `抓取结果/`：按**抓取需求**建分类子目录，一个需求一个文件夹，原始产物只进对应需求的文件夹；走查用截图仍归 `走查/截图/`，两边不混。
- `调研文档/`：建 `README.md` 一行说明——用户要求基于抓取内容产出的文档（现状梳理、行为分析、流程还原、调研结论等）统一放此目录。

### Linear/

- **`AGENTS.md`**：工单流程——读任务用 Linear MCP，不退化成网页抓取，掉线提示重连；处理完自动产出评论草稿（改动范围/内容/链接，结尾 cc @某人），用户手动回评，不代发；每处理一单在 `History.md` 记一行。
- **`History.md`**：表头 `| 日期 | 工单 | 处理内容 | 状态 |`。

## 创建后收尾（必做）

1. 列出已创建的文件清单。
2. 一次性提示待填四件事：① PRD 来源（链接或文件）；② `需求调研/登录说明.md` 的测试站 URL 与账号；③ `AGENTS.md` 的 Linear ticket 链接；④ `figma-preferences.md` 三库口径是否沿用 Kira 默认。
3. 规范八份已随 `references/` 复制到位，无需另行生成；若比对发现共享 `../设计系统/` 或最近项目里有更新版本，提醒用户刷新技能快照（说「同步 scaffold skill」即可）。
